# 会话草稿产品设计

## 要解决的问题

用户在多个会话间并行切换或中断编辑时，尚未发送的草稿容易被遗忘在输入框里；
仅看侧栏标题时，用户分辨不出哪些空闲会话还留有未发送的文字草稿。
本插件在侧栏为空闲草稿会话提供轻量视觉提示，并与列表过滤联动。

## 目标体验与边界

- **草稿识别与持久**：会话输入框包含任意非空白文字（包括随编辑器文本计入的引用）时即视为存在未发送草稿；
  用户离开输入框或刷新页面回到该会话列表时，只要浏览器仍保留草稿，提示状态即持续存在；清空文字后提示随之消除。
  浏览器本地存储不可用时，仍可继续跟踪当前页面内活跃会话的输入变化。

### 侧栏状态图标

- 在普通未归档会话的侧栏条目中，当没有更高优先级的原生运行态、待审批或定时任务提示时，
  标题左侧显示一枚静默铅笔图标提示有未发送草稿；铅笔只承担状态提示与辅助朗读标签，不附带额外编辑操作。
- 原生定时任务时钟等占满左侧状态位时，铅笔主动让位，
  但该会话仍作为有草稿会话被「左侧栏列表三态切换」的「需关注」视图保留。
- 原生空白会话行与已归档会话行不提供该状态位；停用插件后铅笔标记与对三态列表的草稿供稿同步移除。

## 成功标准

| 场景 | 可观察结果 |
| --- | --- |
| 输入与清空草稿 | 在普通会话输入框键入非空白文字并切换至其他会话后，原会话行左侧出现铅笔提示；清空文字后铅笔消失。 |
| 页面刷新恢复 | 留有草稿的会话在页面刷新后无需重新打开输入框，侧栏仍显示铅笔提示。 |
| 原生状态优先级 | 会话存在运行中、待审批或定时任务提示时，优先显示原生状态而不与铅笔重叠。 |
| 与列表三态联动 | 同时启用列表三态切换时，留有草稿（包括被原生时钟遮挡但未发送）的会话留在「需关注」视图；停用本插件后联动解除。 |
